Build a polished, production-quality web application around the existing **Plan My Weekend ADK agent** in this repository.

IMPORTANT:
- Do NOT replace or rewrite the existing ADK agent logic.
- The existing `agent.py` already contains:
  - `weekend_planner` ADK agent
  - Gemini model
  - `search_weekend_knowledge()` tool
  - Gemini embeddings
  - MongoDB Atlas Vector Search RAG
- Reuse the existing agent and MongoDB RAG implementation.
- Do not create a mock AI response.
- The application must actually call the existing ADK agent.

## Goal

Turn the existing Plan My Weekend agent into a beautiful web product that can be demonstrated live and deployed as a single project to Vercel.

The product should feel like a modern AI travel-planning application rather than a developer demo.

Frontend:
- React
- Vite
- TypeScript
- Tailwind CSS
- Modern component-based UI
- Responsive design

Backend:
- FastAPI
- Python
- Existing Google ADK agent
- Existing MongoDB Atlas Vector Search

Deployment:
- Vercel
- One repository/project
- Frontend and backend deployed together
- Do not require a separate backend server for the demo

Use Vercel-compatible API routing/serverless architecture where appropriate.

## Backend API

Create a FastAPI API endpoint such as:

POST /api/plan

Request:

{
  "destination": "Jaipur",
  "days": ["Saturday", "Sunday"],
  "interests": ["photography", "food", "history"],
  "budget": 1500,
  "people": 2,
  "preferences": "Prefer relaxed activities"
}

The endpoint should invoke the existing ADK agent.

Do not duplicate the agent's business logic inside FastAPI.

Create a clean service layer if needed:

frontend
→ FastAPI
→ ADK agent
→ search_weekend_knowledge()
→ MongoDB Vector Search
→ Gemini
→ response

## Response handling

Prefer returning structured JSON from the backend so that the frontend can render the itinerary as UI components.

If the existing agent currently returns plain text, adapt the response parsing carefully without changing the underlying RAG behavior.

Do not fabricate fields that are not present in the agent response.

## Error handling

Handle:
- Missing Gemini API key
- Missing MongoDB URI
- MongoDB connection failure
- Vector Search failure
- Gemini/API errors
- Invalid user input
- Empty search results

Show user-friendly error messages.

Never expose API keys, MongoDB credentials, stack traces or internal errors to the browser.

## Environment variables

Use environment variables.

Expected variables:

GOOGLE_API_KEY
MONGODB_URI
MONGODB_DATABASE
MONGODB_COLLECTION

Do not hard-code any credentials.

Create/update `.env.example` with placeholder values.

Do not commit `.env`.

## Important architecture constraint

Do not create a second AI implementation.

The existing ADK agent is the source of truth.

The web application is a product layer around that agent.

Keep the following concepts clearly separated:

Frontend:
UI and user interaction

FastAPI:
API boundary

ADK:
Agent orchestration and reasoning

RAG tool:
MongoDB Vector Search retrieval

MongoDB:
Knowledge + embeddings

Gemini:
Embedding + generation
